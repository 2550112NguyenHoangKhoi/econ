1. Executive Summary & Full-System Architecture Mind Map

1.1 Executive Summary

The ECON Enterprise Digital Twin is an end-to-end, physics-grounded cyber-physical building energy and indoor environmental management platform. Designed to overcome the operational and architectural limitations of legacy Building Management Systems (BMS), ECON couples real-time physical telemetry with continuous first-principles thermodynamic simulation, online system identification, and generative AI forecasting.

The platform is architected around the core engineering principle: "Never fabricate a measurement". Physical edge microcontrollers report strictly what has been observed; absent or failing sensors cause telemetry fields to be omitted rather than replaced with synthetic constants. In the absence of physical sensors, the Go backend engine executes an autonomous lumped-capacitance 2R1C thermodynamic model, a closed-form Hardy Cross airflow solver, and diurnal occupancy profiles running at 30 FPS.

The complete system spans seven ascending architectural layers—from physical edge silicon to browser-rendered WebGL: 1. Layer 1: Edge Hardware & Sensors: ESP32 DevKit and Raspberry Pi Pico microcontrollers hosting 16+ sensor and actuator modalities across I2C, ADC, 1-Wire, UART, and digital interfaces. 2. Layer 2: Communication & Message Broker: Eclipse Mosquitto MQTT broker with role-based ACLs, DualModeComm (UDP/MQTT/Serial), strict topic hierarchies, and an autonomous edge gateway failsafe daemon. 3. Layer 3: Backend Engine & Simulation: High-throughput Go simulation engine integrating 30 FPS 2R1C thermal ODEs, closed-form Hardy Cross fluid networks, Recursive Least Squares (RLS) room identification, Autonomous Plug-Load Control (APLC), dynamic vacancy setback optimization, pre-cooling loops, and sensorless "Shadow Twin" Automated Fault Detection & Diagnostics (AFDD). 4. Layer 4: AI/ML & Forecasting: Supervised PeakLoadLSTM, Google TimesFM zero-shot foundation models (231M/500M parameters), online Welford learned baselines, and cross-process HTTP IPC with plausibility gating. 5. Layer 5: Database & Persistence: PostgreSQL with TimescaleDB hypertables, 5-minute continuous aggregates, an 8192-capacity lockless write buffer, and 60-second durable JSON state checkpointing. 6. Layer 6: API Layer: 32 REST endpoints and high-speed binary Google FlatBuffers WebSocket streaming at 30 Hz with CSWSH protection and constant-time token verification. 7. Layer 7: Frontend Dashboard: React 18, Vite 5, Three.js / React Three Fiber procedural BIM 3D digital twin with CSG window cutouts, custom GLSL thermal heatmap shaders, and honest Recharts forecast deciles.

2. Zero-Hardware Simulation Path & Developer Quick-Start Guide

The ECON platform provides a fully autonomous, zero-hardware simulation path. Collaborators and new team members can build, execute, debug, and test the entire system without connecting a single microcontroller, wire, or sensor.

2.1 Simulation Architecture & Principles

When physical edge hardware is absent: 1. Autonomous 2R1C Thermal Integration: The Go engine evaluates z.hwFresh() (server/simulation/engine.go:999–1002). When no MQTT packet has arrived for $>20$ seconds (hwStaleAfter), physical sensor pinning disengages. The zone’s air ($T_{\text{air}}$) and wall ($T_{\text{wall}}$) temperatures are governed strictly by the Forward Euler integration of the 2R1C thermodynamic ODEs. 2. Climatological Diurnal Weather Model: If external weather APIs are unreachable, outdoor temperature follows a deterministic Ho Chi Minh City diurnal sinusoid (engine.go:1007–1021): $$T_{\text{out}}(t) = 29.5 + 4.5 \cos\left(\frac{2\pi (t_{\text{hour}} - 15)}{24}\right) \quad [25.0^\circ\text{C}\text{ at dawn to }34.0^\circ\text{C}\text{ at 15:00}]$$ 3. Diurnal Building Occupancy Schedule: Occupancy schedules modulate human density and internal thermal gains based on standard commercial building operating hours (engine.go:2022). 4. Closed-Form Hardy Cross Airflow: Duct static pressures and VAV branch airflows are computed from damper positions and fan curves without requiring physical flow sensors.

3. Layer 1: Edge Hardware & Sensors

3.1 Edge Hardware Architecture Overview

Layer 1 encompasses the physical sensing and actuation hardware deployed within building thermal zones. The architecture uses a dual-microcontroller topology: - Primary Zone Node (ESP32): A dual-core Xtensa LX6 running at 240 MHz. Handles high-speed ADC sampling (True-RMS computation), I2C sensor communications, Wi-Fi DualModeComm networking, and local actuation. - Auxiliary Coprocessor / Lab Desk Node (Raspberry Pi Pico): Powered by the RP2040 dual ARM Cortex-M0+ running at 133 MHz. Acts as a desktop environmental sensor, USB CDC serial bridge, directional PIR headcount monitor, and hardware watchdog supervisor.

3.3 Microcontroller Pin Allocation & Conflict Safeguards

In edge/esp32/src/main.cpp, strict compile-time preprocessor assertions prevent pin collisions that would otherwise cause silent runtime bus failure or silicon damage:

  1. I2C Bus vs IR Blaster Guard (main.cpp:251–253): cpp #if I2C_SDA == 19 || I2C_SCL == 19 #error "I2C pin collides with IR_PIN (GPIO19) - pick another pin via -DI2C_SDA/-DI2C_SCL" #endif Rationale: Earlier board layouts assigned the IR emitter to GPIO 22, which is I2C_SCL. Every 38 kHz HVAC burst clamped the SCL clock line to ground, permanently locking the SHT30 and ACD1200 I2C bus until power-cycle. Moving the IR emitter to GPIO 19 resolved the conflict.

  2. I2C Bus vs Actuator Relay Guards (main.cpp:248–256): cpp #if I2C_SDA == 23 || I2C_SCL == 23 #error "I2C pin collides with RELAY_PIN (GPIO23) - pick another pin via -DI2C_SDA/-DI2C_SCL" #endif #if USE_PLUG && (I2C_SDA == 25 || I2C_SCL == 25) #error "I2C pin collides with PLUG_RELAY_PIN (GPIO25) - pick another pin via -DI2C_SDA/-DI2C_SCL" #endif

  3. 1-Wire Temperature vs IR Receiver Guard (main.cpp:190–192): cpp #if USE_IR_AC && defined(IR_RECV_PIN) && IR_RECV_PIN == 26 #error "SUPPLY_TEMP_PIN collides with IR_RECV_PIN (GPIO26) - cannot use both simultaneously" #endif

  4. ADC Pin Assignment & Wi-Fi SAR ADC2 Isolation:

  5. PLUG_ADC_PIN is on GPIO 34 (ADC1 Channel 6).
  6. STRIP_ADC_PIN is on GPIO 33 (ADC1 Channel 5).

  7. AC_CLAMP_PIN is on GPIO 35 (ADC1 Channel 7). Design Rule: All analog current sensors are assigned strictly to ADC1. On the ESP32, ADC2 is permanently disabled while the Wi-Fi subsystem is active (the SAR ADC2 hardware is shared with the Wi-Fi baseband). Assigning current clamps to ADC2 pins (e.g. GPIO 0, 2, 4, 12–15, 25–27) causes analogRead() to return spurious zeros or crash whenever a packet transmits. Furthermore, GPIO 34 and 35 are physical input-only pins with no internal pull-ups or output drivers, protecting the microcontroller from inadvertent software back-powering.

  8. PIR vs Camera D7 Pin Guard: When the OV7670 camera module is compiled in (-DUSE_CAMERA=1), parallel data line D7 claims GPIO 5. The legacy single-PIR pin assignment (GPIO 5 in older documentation) was migrated to GPIO 18 to allow concurrent camera and motion detection.

  9. Mandatory 5V-to-3.3V Bidirectional Level Shifter for ACD1200 NDIR CO₂: The ASAIR ACD1200 requires a 5V supply to operate its optical incandescent IR lamp. Its internal I2C pull-up resistors tie directly to the 5V rail. Connecting the ACD1200 directly to the ESP32’s 3.3V I2C pins (GPIO 21/22) will over-voltage the SoC’s ESD clamping diodes and permanently degrade the silicon. A bidirectional MOSFET level shifter (BSS138 with 10kΩ pull-ups) is strictly mandatory.

5.2 The 2R1C Lumped-Capacitance Thermodynamic Model

5.2.1 Physical Formulation & Coupled Differential Equations

Each thermal zone is modeled as a 2-Resistor / 1-Capacitor equivalent circuit: - Fast indoor air node ($T_{\text{air}}$) with thermal capacitance $C_{\text{air}}$ ($\text{J/K}$). - Slow structural wall thermal mass ($T_{\text{wall}}$) with capacitance $C_{\text{wall}}$ ($\text{J/K}$). - Inner boundary resistance $R_{\text{in}}$ ($\text{K/W}$) between air and interior wall surface. - Outer envelope resistance $R_{\text{out}}$ ($\text{K/W}$) between wall mass and outdoor ambient air ($T_{\text{out}}$).

The coupled continuous-time differential equations governing the thermal state are:

$$\frac{dT_{\text{air}}}{dt} = \frac{1}{C_{\text{air}}} \left[ \frac{T_{\text{wall}} - T_{\text{air}}}{R_{\text{in}}} + \dot{q}{\text{int}} + \dot{q}{\text{interzone}} - \dot{q}_{\text{cool}} \right]$$

$$\frac{dT_{\text{wall}}}{dt} = \frac{1}{C_{\text{wall}}} \left[ \frac{T_{\text{out}} - T_{\text{wall}}}{R_{\text{out}}} - \frac{T_{\text{wall}} - T_{\text{air}}}{R_{\text{in}}} \right]$$

In state-space matrix notation $\dot{\mathbf{T}} = \mathbf{A}\mathbf{T} + \mathbf{b}$, where $\mathbf{T} = [\,T_{\text{air}},\, T_{\text{wall}}\,]^{\top}$:

$$\mathbf{A} = \begin{bmatrix} -\dfrac{1}{R_{\text{in}}C_{\text{air}}} & \dfrac{1}{R_{\text{in}}C_{\text{air}}} \ \dfrac{1}{R_{\text{in}}C_{\text{wall}}} & -\dfrac{1}{C_{\text{wall}}}\left(\dfrac{1}{R_{\text{in}}}+\dfrac{1}{R_{\text{out}}}\right) \end{bmatrix}, \qquad \mathbf{b} = \begin{bmatrix} \dfrac{\dot{q}{\text{int}} + \dot{q}{\text{interzone}} - \dot{q}{\text{cool}}}{C{\text{air}}} \ \dfrac{T_{\text{out}}}{R_{\text{out}}\,C_{\text{wall}}} \end{bmatrix}$$

5.2.2 Parameter Derivation

  1. Air Thermal Capacitance ($C_{\text{air}}$): $$C_{\text{air}} = \kappa \cdot \rho_{\text{air}} c_{p,\text{air}} \cdot A_{\text{zone}} \cdot h_{\text{ceiling}}$$ where $\rho_{\text{air}} c_{p,\text{air}} = 1206\,\text{J}\cdot\text{m}^{-3}\text{K}^{-1}$, and $\kappa = 5$ is a lump factor accounting for furniture, partitions, and shallow slab thermal mass.
  2. Wall Thermal Capacitance ($C_{\text{wall}}$): $$C_{\text{wall}} = \rho_{\text{concrete}} c_{p,\text{concrete}} \cdot V_{\text{envelope}} \approx 4 \times 10^6\,\text{J/K (default baseline)}$$
  3. Envelope Thermal Resistance ($R_{\text{in}}, R_{\text{out}}$): $$(UA){\text{zone}} = U{\text{wall}} A_{\text{wall}} + U_{\text{roof}} A_{\text{roof}} + U_{\text{part}} A_{\text{part}}, \qquad R_{\text{total}} = \frac{1}{(UA){\text{zone}}}$$ $$R{\text{in}} = 0.40 \cdot R_{\text{total}}, \qquad R_{\text{out}} = 0.60 \cdot R_{\text{total}}$$
  4. Inter-Zone Partition Coupling ($\dot{q}_{\text{interzone}}$): $$\dot{q}{\text{interzone}} = \sum{j \in \text{Adjacent}} \frac{T_j - T_{\text{air}}}{R_{\text{part}, j}}, \qquad R_{\text{part}, j} = \max\Big(0.001,\; 2.0 \cdot (R_{\text{in}} + R_{\text{in}, j})\Big)$$

5.2.3 VAV Sensible Cooling Capacity Normalization

Sensible cooling extraction $\dot{q}_{\text{cool}}$ is normalized by terminal VAV nominal design airflow:

$$\dot{q}{\text{total,nom}} = \dot{q}{\text{int,nom}} + \frac{T_{\text{out}} - T_{\text{sp}}}{R_{\text{in}} + R_{\text{out}}}$$

$$\dot{q}{\text{cool}} = \max\left(0,\; \left(\frac{\dot{m}{\text{vav}}}{\dot{m}{\text{nom}}}\right) \cdot \dot{q}{\text{total,nom}} \cdot \left(\frac{T_{\text{air}} - T_{\text{supply}}}{T_{\text{sp}} - T_{\text{supply}}}\right)\right)$$

where $\dot{m}{\text{vav}} / \dot{m}{\text{nom}}$ is the airflow ratio from the Hardy Cross solver, and $T_{\text{supply}}$ is either measured via DS18B20 or taken from design ($12.0^\circ\text{C}$). The non-negative clamp prevents cooling air from heating zones.

5.2.4 Numerical Integration & Stability Criterion

Integration uses an explicit Forward Euler discretization:

$$T_{\text{air}}^{(k+1)} = T_{\text{air}}^{(k)} + \left[ \frac{T_{\text{wall}}^{(k)} - T_{\text{air}}^{(k)}}{R_{\text{in}} C_{\text{air}}} + \frac{\dot{q}{\text{int}} + \dot{q}{\text{interzone}} - \dot{q}{\text{cool}}}{C{\text{air}}} \right] \Delta t$$

$$T_{\text{wall}}^{(k+1)} = T_{\text{wall}}^{(k)} + \left[ \frac{T_{\text{out}} - T_{\text{wall}}^{(k)}}{R_{\text{out}} C_{\text{wall}}} - \frac{T_{\text{wall}}^{(k)} - T_{\text{air}}^{(k)}}{R_{\text{in}} C_{\text{wall}}} \right] \Delta t$$

Stability Bound: The spectral radius requires $\Delta t < 2 R_{\text{in}} C_{\text{air}} = 2 \tau_{\text{air}}$. At $\Delta t \approx 0.033\,\text{s}$, the solver operates orders of magnitude inside the stability threshold ($\tau_{\text{air}} \sim 600 - 3600\,\text{s}$). State values are clamped to $[5.0^\circ\text{C}, 50.0^\circ\text{C}]$.

5.3 Hardy Cross Fluid Airflow Simulation

5.3.1 Looped Formulation & Closed-Form Star Reduction

Turbulent head loss $h$ across duct segments obeys the Atkinson equation $h = K \cdot Q^2$. In ECON's parallel VAV star network, $V$ parallel branches share a common supply plenum pressure drop $\Delta P = P_{\text{ahu}}$. The looped Newton-Raphson formulation reduces to an exact closed-form algebraic solution:

Each branch carries airflow: $$Q_v = \sqrt{\frac{\Delta P}{K_v}} \implies K_v^{-1/2} = \frac{Q_v}{\sqrt{\Delta P}}$$

Summing across all $V$ branches yields total airflow $Q_{\text{tot}} = \sqrt{\Delta P} \sum K_v^{-1/2}$. Inverting yields equivalent system resistance $R_{\text{system}}$:

$$R_{\text{system}} = \left( \sum_{v=1}^V K_v^{-1/2} \right)^{-2} = \left( \sum_{v=1}^V \frac{1}{\sqrt{K_v}} \right)^{-2}$$

Coupling with the supply fan curve ($P_{\max}$ split between fan resistance $K_{\text{fan}}$ and $R_{\text{system}}$):

$$Q_{\text{tot}}^2 = \frac{P_{\max}}{K_{\text{fan}} + R_{\text{system}}}$$

Static operating pressure at the AHU plenum is:

$$\Delta P = P_{\text{ahu}} = R_{\text{system}} \cdot Q_{\text{tot}}^2 = R_{\text{system}} \cdot \left(\frac{P_{\max}}{K_{\text{fan}} + R_{\text{system}}}\right)$$

Individual branch flows are directly extracted:

$$Q_v = \sqrt{\frac{\max(0, P_{\text{ahu}})}{K_v}}$$

5.3.2 Fan Sizing & Static Pressure Ceiling

The fan sizing function sizeFanToBuilding() sets: $$P_{\max} = P_{\text{design}} \cdot \left( \frac{K_{\text{fan}}}{R_{\text{system, design}}} + 1.0 \right)$$ Static pressure is clamped to a physical safety ceiling: $P_{\text{ahu}} \le 650.0\,\text{Pa}$. When a VAV damper closes, $R_{\text{system}}$ rises, increasing plenum pressure and redistributing airflow into adjacent open zones.

5.4 Recursive Least Squares (RLS) Online Room Dynamics

5.4.1 System Identification Formulation

Implemented in server/simulation/dynamics.go:1–989. Identifies physical room parameters online by regressing two continuous differential equations:

  1. Thermal Response ODE: $$\frac{dT}{dt} = \theta_0 (T_{\text{out}} - T_{\text{in}}) + \theta_1 \cdot \text{FlowRatio} \cdot (T_{\text{in}} - T_{\text{supply}}) + \theta_2 \cdot N_{\text{occ}} + \theta_3$$
  2. $\theta_0$: Envelope thermal conductance ($h^{-1}$); thermal time constant $\tau = 1/\theta_0$ (hours).
  3. $\theta_1$: VAV cooling authority ($h^{-1}$ per unit flow $\cdot \Delta T$); physically $< 0$.
  4. $\theta_2$: Heat gain per occupant ($^\circ\text{C}/h$ per person); physically $\ge 0$.

  5. $\theta_3$: Unmetered base electrical and solar load ($^\circ\text{C}/h$).

  6. Ventilation & CO₂ Mass Balance ODE: $$\frac{dC}{dt} = \phi_0 \cdot N_{\text{occ}} + \phi_1 (C_{\text{out}} - C) + \phi_2$$

  7. $\phi_0$: CO₂ generation rate per person ($\text{ppm}/h$ per person).
  8. $\phi_1$: Air-change rate ACH ($h^{-1}$); physically $> 0$.
  9. $\phi_2$: Ambient baseline drift ($\text{ppm}/h$).

5.4.2 Midpoint Bias Cancellation & Errors-in-Variables

Sampling occurs at $\Delta t_{\text{sample}} = 300\,\text{s}$ (5 minutes). Evaluating target derivative $y = (T_t - T_{t-1})/\Delta t$ against endpoint $T_t$ introduces measurement error $-\varepsilon_t$, creating spurious negative terms in covariance. ECON evaluates regressors at the interval midpoint:

$$T_{\text{mid}} = \frac{T_t + T_{t-1}}{2}, \qquad C_{\text{mid}} = \frac{C_t + C_{t-1}}{2}$$

This cancels correlated noise expectation $\mathbb{E}[\varepsilon_t^2 - \varepsilon_{t-1}^2]/(2\Delta t) = 0$, eliminating asymptotic bias.

5.4.3 RLS Update Equations & Anti-Windup

  1. Information Metric: $\text{info} = \mathbf{x}^\top P \mathbf{x}$.
  2. Information-Gated Forgetting: $\lambda = 0.999$ if $\text{info} \ge 10^{-3}$; else $\lambda = 1.000$ (prevents covariance windup during steady state).
  3. Gain Vector: $\mathbf{k} = \frac{P \mathbf{x}}{\lambda + \mathbf{x}^\top P \mathbf{x}}$.
  4. Parameter & Covariance Update: $$\theta \leftarrow \theta + \mathbf{k}(y - \mathbf{x}^\top \theta), \qquad P \leftarrow \frac{1}{\lambda}\left(P - \mathbf{k}\mathbf{x}^\top P\right)$$
  5. Trace Bounding: If $\text{trace}(P) > 10^4$, rescales $P \leftarrow P \cdot \frac{10^4}{\text{trace}(P)}$.
  6. Bayesian Ridge Prior (Leaky RLS): Relaxes unconstrained parameters toward physical prior $\theta_{\text{prior}} = [0.5, -1.0, 0.05, 0.2]^\top$: $$w_i = \text{clamp}\left(\frac{P_{ii}}{50.0},\, 0,\, 1\right), \qquad \theta_i \leftarrow \theta_i + 0.002 \cdot w_i \cdot (\theta_{\text{prior}, i} - \theta_i)$$

5.4.4 Closed-Form Forward Trajectory Projection

With drivers held constant, the ODE integrates analytically:

$$k = \theta_0 - \theta_1 \cdot \text{FlowRatio}, \qquad T_{\text{eq}} = \frac{\theta_0 T_{\text{out}} - \theta_1 \cdot \text{FlowRatio} \cdot T_{\text{supply}} + \theta_2 N_{\text{occ}} + \theta_3}{k}$$

$$T(t) = T_{\text{eq}} + \big(T(0) - T_{\text{eq}}\big) e^{-k t}$$

Time required to cross comfort limit $T_{\text{limit}}$:

$$t_{\text{limit}} = -\frac{1}{k} \ln\left(\frac{T_{\text{limit}} - T_{\text{eq}}}{T(0) - T_{\text{eq}}}\right) \times 3600\,\text{seconds}$$

  • Source Reference: server/simulation/dynamics.go:1–989, recommend.go:299–409.

5.6.2 Actuation & Avoided Carbon Integration

5.7 Forecast-Driven Pre-Cool Decision Loop

Implemented in server/precool.go:1–226 and server/simulation/engine.go:892, 938–942. 1. Runs every 5 minutes (precoolLoop). 2. 5.8 Vacancy Setback Optimizer

Implemented in server/simulation/engine.go:862–974 and server/simulation/dynamics.go:879–950. 1. Manual Override Latch: Respects manual human changes (z.OverrideUntil) for 15 minutes. 2. 5.9 Automated Fault Detection and Diagnostics (AFDD)

Implemented in server/simulation/engine.go:125–135, 1308–1316, 2186–2198, recommend.go:320–408, and carbon.go:420–530. 1. Sensorless Shadow Twin: Every zone bound to hardware runs a parallel, sensor-free 2R1C simulation. It is never pulled toward physical measurements. 2. Residual Tracking: Raw residual $r = |T_{\text{hw}} - T_{\text{shadow}}|$ is filtered via an Exponential Moving Average ($\alpha = 0.02$): $$\text{ResidualEma} \leftarrow \text{ResidualEma} + 0.02 \cdot \big(r - \text{ResidualEma}\big)$$ 3. Capability Shortfall: Flags when full cooling equilibrium $T_{\text{eq,full}} > T_{\text{sp}} + 0.8^\circ\text{C}$ ("Undersized VAV / delivery fault").

8.3 WebSocket Streaming Protocol & Binary Frames

  • Endpoint: /ws
  • Protocol: Binary WebSocket frame carrying Google FlatBuffers bytes (Telemetry.SimState).
  • Cadence: Broadcast at ~30 Hz driven by the engine ticker (server/simulation/engine.go:2713–2856).
  • Frame Schema (server/schema/telemetry.fbs):
  • ZoneData: Zone ID, temperature, setpoint, deadband, occupants, electrical load, lighting state, humidity, CO₂, plug watts, plug shed flag, supply temperature, power strip watts, AFDD residual.
  • VavData: Damper position, airflow rate.
  • GlobalData: Total building load ($MW$), cooling output ($MW$), plant COP, energy saved ($MW$), BESS state of charge ($SOC\%$), average CO₂, total plug load ($kW$), auto-pilot status, AHU static pressure ($Pa$).
  • Root SimState: Vectors of ZoneData, VavData, and GlobalData with epoch millisecond timestamp.
  • Non-Blocking Dispatch: Finished byte buffers are broadcast asynchronously outside the engine lock to prevent network lag from stalling simulation physics.
